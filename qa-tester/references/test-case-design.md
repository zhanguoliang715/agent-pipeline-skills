# 测试用例设计方法
> 配套 SKILL：qa-tester（具体版本见该 SKILL.md 的 version 字段，不在此写死）
> 本文件版本：1.0.2

## 每个 P0 功能至少覆盖四类

1. **正常流**：用户按预期操作，得到预期结果。
2. **边界值**：空值、0、最大值、最小值、刚好多一个字符/少一位。
3. **异常输入**：
   - 类型不对（要数字给字母）；
   - 超长字符串；
   - 特殊字符（引号、尖括号、换行、Emoji）；
   - 并发/重复提交（连点两下、刷新重试）。
4. **权限/状态**：未登录能不能访问、未满足前置条件能不能跳到下一步。

## 第五类：非功能需求与风险预案核对（必做）

把 PRD 第 6 节「非功能需求」和第 9 节「依赖、约束与风险」里的每一条可验证项，转成验证用例——功能正确不等于设计承诺落地：

- **性能指标**（如"列表加载 < 2s"）：实际测量并记录数值，超标记 bug。
- **安全要求**（如"密码不得明文存储"）：检查存储形态、日志输出，不符记 bug。
- **风险预案**（如"基于单调时钟计算避免系统时间跳变"）：验证实现是否按预案落地（如是否真的用了单调时钟而非系统时间）；没落地记 bug，严重程度按影响定（一般到严重）。
- **外部依赖**：声明"无外部依赖"的，确认实现没有偷偷引入未声明依赖。

每条非功能需求/风险预案**至少一条验证用例**，结果在测试报告「非功能与风险预案核对」一节逐条列出（条目 | 验证方式 | 结果）。漏了任何一条，check_qa.py 会拦下报告。

## 执行记录要求

- 每个用例记录：步骤 → 输入 → 预期 → 实际 → 通过/失败。
- 失败的用例必须配 BUG 单，BUG 单里写最小复现路径。
- 安全漏洞被开发修复后，本环节负责**功能回归**：除了复验该安全 bug，还要重跑受影响功能的旧用例，确认修漏洞没有改崩正常功能；回归通过后再交回安全环节复测。
