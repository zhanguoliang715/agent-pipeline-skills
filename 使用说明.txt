软件开发流水线 Skill 使用说明
=================================

这套东西把"写需求 -> 评审 -> 开发 -> 测试 -> 安全攻防"固化成五个独立 Skill，
另加一个总调度 pipeline-orchestrator 把它们串成流水线，靠固定文件名和门禁
规则衔接，不靠口头交接。

--------------------------------------------------
目录结构
--------------------------------------------------
D:\agent skill\
├── product-manager\            棒1：写 PRD
├── requirement-reviewer\       棒2：需求评审
├── software-developer\          棒3：写代码
├── qa-tester\                  棒4：功能测试
├── security-pentester\          棒5：安全攻防（终点）
├── pipeline-orchestrator\      总调度：一句话跑完整条流水线（不可单独部署）
├── scripts\                    仓库级（仅整套部署需要）
│   ├── regression_test.py      行为回归测试（机器实测退出码契约）
│   └── smoke_pipeline.py       端到端冒烟（五棒门禁链 + 打回/修复路由）
├── .github\workflows\           CI：validate + regression + smoke（GitHub Actions，仅整套部署需要）
├── validate_pipeline.py        全流水线一致性校验器（仅整套部署需要）
├── USAGE.md                     详细使用说明
├── README.md                    GitHub 门面文档
├── 使用说明.txt                  本文件（中文快速上手）
├── 提示词模板.txt                傻瓜式提示词
└── LICENSE                      MIT 协议

每个 skill 目录内部：
  SKILL.md           指令入口
  references\        知识库（模板、清单、规范）
  scripts\           可执行校验脚本

--------------------------------------------------
独立部署
--------------------------------------------------
棒1-5（五个单棒）各自可单独拷出使用，不需要整套仓库、orchestrator、
仓库级脚本或 CI。拷走整个棒目录后，以该棒目录为 CWD 跑校验脚本：

  棒1 product-manager        python scripts\check_prd.py 01-prd.md
  棒2 requirement-reviewer   python scripts\check_review.py 02-requirement-review.md
  棒3 software-developer     python scripts\check_source.py 03-source\
  棒4 qa-tester              python scripts\check_qa.py 04-qa-test-report.md
  棒5 security-pentester     python scripts\scan_security.py 03-source\

单棒目录是自包含的：SKILL.md（文末有"独立部署"章节）+ references\（配套
本棒自身）+ scripts\，产物文件名固定不变。运行时依赖见各棒 SKILL.md（四棒
只用标准库，安全棒另需 pip install "bandit==1.9.4"，不装只跑正则层）。
pipeline-orchestrator 不可单独部署（只调度不产出，必须与五棒同仓库根）。

--------------------------------------------------
角色职责和产出
--------------------------------------------------
棒0 pipeline-orchestrator（总调度，先跑它）
  干什么：按顺序叫 1-5 棒干活，检查每棒产物和门禁脚本，
          打回自动路由（评审 NO 退回 PM、测试致命打回开发、
          安全高危修完再攻），最后打包五件套交付
  门禁：确认走完整条流水线 + 确认工作目录，才启动

棒1 product-manager
  产出：01-prd.md
  干什么：把原始想法写成边界清楚、可验收的 PRD
  门禁：先问"你真要做吗"，最多 3 轮追问

棒2 requirement-reviewer
  产出：02-requirement-review.md
  干什么：评审 PRD 可执行性，六维度打分，结论 YES / NO / 退回
  门禁：收到的不是 PRD 就退回；最多打回 2 次（共 3 次评审机会）

棒3 software-developer
  产出：03-source\（目录，含 README）
  干什么：按 YES 的 PRD 写可运行代码
  门禁：02 结论不是 YES 不开工

棒4 qa-tester
  产出：04-qa-test-report.md
  干什么：搭环境跑主流程，列 bug 分级
  门禁：按 README 起不来 = 致命 bug 直接打回

棒5 security-pentester
  产出：05-security-pentest-report.md
  干什么：授权门禁后多轮攻防，高危修完再攻
  门禁：外部/公网目标一律拒绝

--------------------------------------------------
怎么跑一条流水线
--------------------------------------------------
一个空工作目录里按顺序产出固定文件名：

工作区\
├── 01-prd.md
├── 02-requirement-review.md
├── 03-source\
├── 04-qa-test-report.md
├── 05-security-pentest-report.md
└── history\                 覆盖写前的历史归档

推荐让总调度跑：说"走流水线，我要做【项目名】，想法是【一句话】"，
orchestrator 会从棒 1 一路叫到棒 5，打回自动路由，最后给你五件套清单。
也可以单棒直接叫：说"帮我写 PRD / 审需求 / 写代码 / 测程序 / 做安全测试"。

每棒交稿前跑对应脚本做结构校验（在工作区根目录）：

  python product-manager\scripts\check_prd.py 01-prd.md
  python requirement-reviewer\scripts\check_review.py 02-requirement-review.md
  python software-developer\scripts\check_source.py 03-source\
  python qa-tester\scripts\check_qa.py 04-qa-test-report.md
  python security-pentester\scripts\scan_security.py 03-source\

--------------------------------------------------
退出码（两套，别混）
--------------------------------------------------
四棒 check 脚本（check_prd / check_review / check_source / check_qa）：
  0 = 通过
  1 = 缺内容（缺章节/缺结论/缺 README 等）
  2 = 业务警告，各脚本语义不同：
        check_prd      = 占位残留（[ ] / 【 】 / < > 未替换）
        check_review   = 占位残留
        check_source   = 依赖/构建目录混入交付包
        check_qa       = 有未修复致命/严重项
  3 = 路径不存在（文件或目录）
  缺参数 = 2（用法错误，与业务警告共用 2 号）

安全棒 scan_security.py（scan_danger.py 同此契约）：
  0 = 干净
  1 = 有 HIGH
  4 = 有 MED（无 HIGH）
  3 = 目录/路径不存在
  2 = argparse 用法错误（命令行写错）
  5 = 扫描工具自身故障（bandit 崩/JSON 坏/有 .py 但 0 行），不能当干净

--------------------------------------------------
环境要求
--------------------------------------------------
- Python 3.9 以上
- 四棒检查脚本和回归测试只用标准库，不用装任何东西
- 安全棒可选深度扫描：pip install "bandit==1.9.4"
  不装也能跑，只跑正则粗扫

--------------------------------------------------
自检
--------------------------------------------------
改完任何 skill 或脚本后，跑三个校验：

  python validate_pipeline.py         # 结构一致性（六棒、references 不悬空、scripts 存在）
  python scripts\regression_test.py   # 行为回归（六棒脚本退出码契约，机器实测）
  python scripts\smoke_pipeline.py    # 端到端冒烟（五棒门禁链 + 打回/修复路由，机器实测）

三个都退出 0 = 全绿。validate 管"结构齐不齐"，regression 管"行为对不对"，
冒烟管"整条调度链跑不跑得通"。
