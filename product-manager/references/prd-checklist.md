# PRD 交付前自查清单
> 配套 SKILL：product-manager（具体版本见该 SKILL.md 的 version 字段，不在此写死）
> 本文件版本：1.0.1

> 每一条都要能打勾，打不了勾就回去补。审核员会按这张表挑问题。

## 完整性
- [ ] 有一句话目标概括，且读者能复述出来
- [ ] 目标用户具体，不是"所有用户/广大群众"
- [ ] 每个用户故事都对应至少一个 FR
- [ ] 功能需求全部编号（FR-01…），没有遗漏
- [ ] 主流程之外至少写了一条异常分支

## 可执行性（审核员重点盯）
- [ ] 每条 FR 的验收标准是**可判定**的：能回答"做到了没有"，而不是"感觉好不好"
- [ ] 没有出现"友好""流畅""快速""美观""尽量"这类主观词
- [ ] 范围边界明确写了"本期不做什么"
- [ ] 没有把技术方案写进需求（例：不应写"用 Redis 做缓存"，只写"列表 2 秒内返回"）
- [ ] 外部依赖、第三方账号、数据来源都列出来了

## 一致性
- [ ] 用户故事 → FR → 验收标准三者能一一对应，没有孤儿需求
- [ ] 优先级标注清楚，MVP 范围明确
- [ ] 没有自相矛盾的描述（例：一边说"免费"一边要求"支付"）

## 常见被打回原因（规避）
- "做一个像 XX 一样的 APP"——没说清楚到底做哪几个功能
- 验收标准写"页面好看"——测试无法判定
- 没写不做什么——开发做到一半被塞新需求
- 依赖了一个没人知道是否存在的内部接口
