# [产品/功能名] 需求文档（PRD）

## 1. 背景与目标
- 一句话概括（写在本节最前）：我们要为【谁】在【什么场景】下解决【什么问题】，成功后【可量化指标】。
- 业务背景：[为什么要做这件事，当前现状是什么痛点]
- 业务目标：[做完后要达成什么，最好有可量化指标，例：注册转化率提升 20%]

## 2. 目标用户与场景
- 目标用户：[角色/画像，例：已注册 7 天内的新用户]
- 核心使用场景：[用户在什么情况下会用，例：晚上到家后想快速记录今日体重]
- 不服务的人群：[谁不在本期范围内]

## 3. 用户故事
- US-1：作为 [角色]，我希望 [动作]，以便 [价值]。
- US-2：……

## 5. 业务流程
主流程（文字或 mermaid）：

异常分支：
- 当 [异常条件] 时，系统应 [表现]。

## 6. 非功能需求
> 本节只写"系统应做到什么"，不写"代码怎么实现"。例：写"密码不得明文存储"是要求（可以）；写"用 bcrypt 加盐哈希"是技术方案（不可以，归开发）。
- 性能：[如：列表加载 < 2s]
- 兼容性：[如：iOS 14+ / 主流浏览器]
- 权限：[谁能看、谁能改]
- 安全：[如：密码不得明文存储、敏感操作需二次确认、错误不得向用户暴露堆栈]——只写要求，不指定算法/框架。
