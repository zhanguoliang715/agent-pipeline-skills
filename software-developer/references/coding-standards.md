# Software Developer 工程规范
> 配套 SKILL：software-developer（具体版本见该 SKILL.md 的 version 字段，不在此写死）
> 本文件版本：1.0.1

## 技术选型原则
- 优先满足 PRD 的非功能需求，不要 over-engineering。
- 命令行/脚本工具：Python 3 标准库优先。
- 页面/可视化：单文件 HTML+原生 JS 优先，除非 PRD 明确要求框架。
- 数据存储：默认文件（JSON/CSV/SQLite），不要默认上数据库服务。
- 选型要一句话理由，写进 README。

## 代码规范
- 文件名、函数名见名知意，不写 `tmp1.py`、`do_stuff()`。
- 每个公开函数写一行 docstring：输入、输出、副作用。
- 关键业务逻辑旁注释 `# FR-xx` 对应 PRD 编号。
- 错误不能静默吞掉：`except: pass` 是禁止项；捕获后要打印/返回有意义的错误信息。
- 用户输入一律校验长度/类型/范围，不要假设输入合法。

## 安全基线（给 Security Pentester 留测试空间，也别留致命伤）
- 不拼接 SQL 字符串，用参数化查询。
- 不把用户输入直接拼进 HTML/命令/Shell。
- 密钥、token、数据库密码一律走环境变量或配置文件，代码里只 `os.environ.get()`。
- 不打印敏感信息到日志。

## 交付前必跑
1. 删掉中间产物（`__pycache__/`、临时输出文件、测试数据库）。
2. 在一个新目录按 README 从零装依赖、启动，确认主流程通。
3. 故意喂一个非法输入，确认程序不崩、有友好报错。

## 被测试打回时
- 先看 bug 复现步骤，本地复现后再改。
- 改完跑一遍原 bug + 相关旧用例，不要只修这一个点。
- 不要为了过测试硬改测试预期——需求没变，就改实现。
